# AGENTS.md

Operational instructions for coding agents working in this repository.

## Project Status

`socials-pages` builds Dennis' link-in-bio page from `socials.yml` and
publishes it with GitHub Pages (`.github/workflows/pages.yml`, on every push to
`main`). It replaces the self-hosted FastAPI app in `~/dev/socials`.

## Stack

- Python 3.12 build script, Jinja2 template, PyYAML, Pillow
- Output is plain HTML and CSS: no JavaScript, no external resources
- GitHub Pages cannot set HTTP headers, so the CSP is a `<meta>` tag in
  `socials_pages/templates/index.html`

## Important Files

- `socials.yml`: the page content. The owner edits it in the GitHub web editor.
- `socials_pages/content.py`: YAML loading, validation, URL normalisation; collects
  all problems with line numbers. Messages are German.
- `socials_pages/build.py`: renders `index.html` and writes assets into `_site/`.
- `socials_pages/images.py`: avatar to 512x512 WebP, strips EXIF/GPS.
- `socials_pages/platforms.py`: platform list, URL detection, inline SVG icons.
- `socials_pages/icons.json`: generated by `scripts/build_icons.py`, do not edit by hand.
- `tests/`: pytest suite; run `.venv/bin/pytest`.

## Rules

- Keep the page free of JavaScript and external resources.
- Asset URLs stay relative so the page works under `/<repo>/` as well as on the custom domain.
- Only `http`, `https` and `mailto` links may reach the page (`content.normalize_url`).
- Pin new GitHub Actions to a full commit SHA with the version as a comment.
- Update both lock files when changing dependencies.
